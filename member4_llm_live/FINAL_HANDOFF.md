# Member 4 — Final API and Team Handoff

**Status:** Hackathon MVP, ESCO v1.2.1; live Gemini requests require your own configured credentials and available model quota. **Not a validated certification or job-readiness score.**

## What is delivered

- Streamlit learner quiz UI (`app.py`), fixed to display dynamically generated skill labels.
- FastAPI JSON service (`api.py`) with autogenerated OpenAPI/Swagger documentation.
- Fixed curated question bank (60 questions, five ESCO concepts; visualization mapping provisional).
- ESCO v1.2.1 concept URI validation, job-driven quiz selection, optional Gemini generation, per-skill score estimates.
- BKT and smoothed-accuracy baselines. **BKT prior/guess/slip parameters are defaults, not fitted to learner data.**
- JSON handoffs: `learner_estimates` maps ESCO URI to number in [0,1]; `estimate_sources` explains derivation and unverified status.
- Local tests, with mocked/no live Gemini call.

## Folder structure

- `api.py`: HTTP endpoints
- `app.py`: local Streamlit UI
- `src/learner_model.py`: estimates (`estimate_skill_knowledge` function is Member 4's unchanged interface)
- `src/job_assessment.py`: Member 2 payload validation and coverage
- `src/quiz_engine.py`: question selection/grading
- `src/llm_questions.py`: Gemini structured generation and structural checks
- `src/universal_assessment.py`: self-report fallback with source attribution
- `data/esco_skills_en.csv`: ESCO v1.2.1 skill taxonomy
- `data/questions.json`: starter bank
- `tests/`: unit/integration tests

## Install and start (Windows PowerShell)

From this project's folder:

```powershell
python -m pip install -r requirements-llm.txt
python -m pytest -q
python -m uvicorn api:app --host 127.0.0.1 --port 8000
```

Open `http://127.0.0.1:8000/docs` for interactive HTTP API docs or `http://127.0.0.1:8000/openapi.json` for the schema. In a **second terminal**, optionally start the existing UI with `python -m streamlit run app.py` (port 8501). UI calls the modules directly; it does **not** call HTTP endpoints.

For Gemini-backed questions, configure in the same terminal as Uvicorn:

```powershell
$env:GEMINI_API_KEY="paste-key-locally-not-in-repo"
$env:GEMINI_MODEL="gemini-3.5-flash-lite"
```

The default model name reflects Google's error surfaced during this project; access/quotas can change. Replace it with a model your Gemini account actually permits. Live requests are not covered by unit tests. Do not commit secrets or learner history to Git.

For an HTTP server **reachable by other teammates**, set an access token and keep the server on a private, trusted network:

```powershell
$env:API_SERVICE_KEY="choose-a-long-random-secret"
```

Call `/v1/*` with `Authorization: Bearer <API_SERVICE_KEY>`. The local development examples below assume the token is unset. **Do not expose this MVP directly on the public Internet** without HTTPS termination, persistent session storage, robust rate limits, request logging protections and operational safeguards. `/health` and `/docs` are informational public paths even if a token is configured.

## JSON APIs

### GET `/health`

Returns status, ESCO version, bank size, vocabulary size, and whether a Gemini key is present (not the key).

### POST `/v1/skills/coverage`

Request:

```json
{
  "job_skills": [
    {"esco_id": "http://data.europa.eu/esco/skill/598de5b0-5b58-4ea7-8058-a4bc4d18c742", "label": "SQL", "importance": 0.9}
  ]
}
```

Response: `{"coverage": [{"esco_id": "...", "label": "...", "importance": 0.9, "canonical_label": "...", "question_count": 12, "mapping_status": "direct", "coverage": "assessable"}]}` (illustrative). Allowed coverage: `assessable`, `assessable_provisional`, `no_question_bank`, `provisional_mapping`, `unknown_esco_id`.

### POST `/v1/assessments/start`

Request:

```json
{
  "job_skills": [
    {"esco_id": "http://data.europa.eu/esco/skill/598de5b0-5b58-4ea7-8058-a4bc4d18c742", "label": "SQL", "importance": 0.9}
  ],
  "questions_per_skill": 3,
  "generate_missing": false,
  "max_ai_skills": 3,
  "include_provisional": false
}
```

Response fields: `assessment_id`, `expires_in_seconds` (3600), `questions` (only public fields, **no answer keys**), `coverage`, `generation_errors`, `unassessed_esco_ids`, `notice`.

Question object fields: `question_id`, `esco_id`, `skill_label`, `difficulty`, `topic`, `prompt`, `options`. Save `assessment_id` and respond once to every question. With `generate_missing=true`, Gemini is called **only** for recognized but uncovered ESCO concepts. Failures are returned as sanitized `generation_errors`; uncovered skills may then use explicitly marked optional self-rating.

### POST `/v1/assessments/submit`

Request:

```json
{
  "assessment_id": "<id returned by /start>",
  "answers": [
    {"question_id": "<id from questions>", "selected_option": 2}
  ],
  "self_ratings": {}
}
```

`selected_option` is a **zero-based integer**. Submit one response for **every** question returned. Optional `self_ratings` keys are ESCO URIs for requested skills with no questions, with numeric values 0–1. Submit is single-use; a second call returns 409.

Response:

```json
{
  "learner_estimates": {"<esco_uri>": 0.63},
  "estimate_sources": {"<esco_uri>": {"method": "experimental_bkt", "estimate": 0.63, "verified": false}},
  "smoothed_accuracy": {"<esco_uri>": 0.6},
  "summary": {"answered_questions": 3, "correct": 2},
  "notice": "Experimental, uncalibrated BKT parameters; not certified mastery."
}
```

The numbers above illustrate output **shape only**, not expected values.

### POST `/v1/estimates/from-history` (trusted internal service)

For Member 5 or another trusted service which **has already graded answers**, bypass the HTTP quiz flow:

```json
{
  "learner_id": "L001",
  "method": "bkt",
  "interaction_history": [
    {"learner_id": "L001", "question_id": "Q001", "esco_id": "<official ESCO URI>", "correct": 1, "timestamp": "2026-10-10T12:00:00Z"}
  ]
}
```

Returns `{ "learner_estimates": { "<esco_uri>": 0.7 }, "method": "bkt", "notice": "..." }`. This endpoint trusts the caller's `correct` fields; therefore restrict it to trusted authenticated services. In this MVP an API token, when configured, applies to **all** `/v1/*` routes.

## Team responsibilities and contract

**Member 2 → Member 4:** Send `job_skills` as `[{"esco_id": "official ESCO skill URI", "label": "official skill name", "importance": 0..1}]`, frozen to **ESCO v1.2.1**. `d` instead of `importance` is accepted by `parse_job_skills` internally, but the HTTP schema uses `importance`.

**Member 4 → Member 5:** Read `learner_estimates` from `/submit`: a dictionary `{ESCO URI: estimated_score_0_to_1}`. Also read `estimate_sources` so recommendations can warn that a score is BKT on unreviewed AI questions or is a self-rating. Missing skills are **not automatically 0** and should be presented as unknown/unassessed.

**Member 5:** Compute gap using the agreed project formula `priority(s) = demand(s) * (1 - mastery(s))` only for assessed values, and choose an explicit policy for unassessed skills. The course recommender is outside this repo.

## Known limitations

1. Only 60 curated questions, and coverage across all ESCO concepts is via **on-demand drafts or self-report**, not a validated full quiz bank.
2. Gemini-generated questions are checked for structure but **not independently fact-checked**; wrong keys or poorly scoped items remain possible.
3. Assessment BKT parameters are illustrative, not fitted/calibrated; a value of 0.8 is **not a proven 80% probability of job competence**.
4. Some occupational skills require hands-on tests; multiple-choice performance measures related knowledge only.
5. Session storage is **in-memory** with one-hour expiry; server restart clears assessments, and multiple Uvicorn workers won't share sessions. Run a **single worker** for the demo.
6. No durable learner accounts/database, formal item analysis, calibrated tests, public deployment authentication infrastructure, distributed rate limiting, or cost guarantees.
7. Gemini free-tier availability, billing and quota are external dependencies; no network tests were executed by the local suite.

## Demo/acceptance checklist

1. Install, run `pytest`, start Uvicorn, view `/docs`.
2. `GET /health` succeeds.
3. `POST /v1/assessments/start` with a directly supported ESCO URI returns 3 items without answer keys.
4. Submitting one answer per question returns `learner_estimates` and `estimate_sources`.
5. Invalid skill URI returns 422; repeated submission returns 409.
6. Optional: configure a Gemini key and start a job with a missing ESCO skill to test generation; if quota is unavailable, expect sanitized `generation_errors` and self-rating fallback.
7. Pass `learner_estimates` to Member 5 and display missing skills distinctly from zero values.
